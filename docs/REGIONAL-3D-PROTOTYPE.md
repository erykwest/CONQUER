# CONQUER — Regional map 3D: global microcell-first experiment

**Branch:** \`3dregionmap\` · **Viewer:** \`lab/3dregionmap.html\`  
**Status:** working WebGL2 prototype, source-linked World Lab 2D, synthetic geometry/input regressions. Do not merge to production without real-browser performance/visual review.

## Design reference

Inspired conceptually by [Red Blob Games' Mapgen4](https://github.com/redblobgames/mapgen4): build a dense dual/Voronoi-like mesh first and use that foundation to form terrain, coastlines and outlines. Unlike Mapgen4, this experiment uses its own simple spatially local Voronoi clipper over a jittered triangular lattice. No code or external packages have been copied or vendored from Mapgen4.

The World Lab is authoritative, with a **square grid of 630 logical centers** (30×21 by default). Each logical center stores eight immediately available neighbor slots, ordered **NW, N, NE, W, E, SW, S, SE**, and map-exterior slots are `null`. Access with `window.ConquerRegion8Neighbors(macroId)` or `snapshot.neighbors8[macroId]`. The square lattice is *only an index* and does **not** prescribe the shape of a territory.

Actual territory polygons are generated by `src/regional-hex-aggregation.js`:

1. Spawn **exactly 20** seeded fine Voronoi sites per logical center, using a globally staggered triangular/hexagonal lattice, randomized positions and an independently sampled size factor **0.5×–1.5×**.
2. Build the actual fine-cell Voronoi polygons and group their 20 IDs by the corresponding square logical center.
3. Extract the **exact shared outer edge loop** of each 20-cell group. Macro territories therefore have organic, irregular outlines with roughly 25–40 boundary vertices, not square or macro-scale hexagonal footprints.
4. Adjust a small macro-level power weight until the **aggregated territory area is within ±10%** of the world mean, checking every territory individually. The fine site/union geometry remains authoritative in both the World Lab SVG and 3D preview.
5. Use the original seed for deterministic retries of a rare degenerate fine-site pattern, never changing macro centers, terrain or adjacency.

The fixed eight-slot neighborhood is *logical*. In a planar tessellation, diagonals need not share a full border; it is therefore incorrect to promise eight **physical** edges per Voronoi territory. Tests enforce that every physical border connects two territories in their eight-slot neighbor set. Older hex-staggered JSON maps remain remappable by saved row/column position.

## Fivefold contour deformation (November 2026)

The irregular Voronoi terrain now receives **5× the former maximum fine-site displacement as a continuous vertex-space warp**: at World Lab deformation value 150 the full requested displacement is about **22 world units**, and at deformation 360 it is about **29 world units**. Each point is transformed by two coordinated sinusoidal shears; the waves vanish at the outer map edges. The square logical centers and the original twenty Voronoi IDs **do not move**.

The transformation is shared between adjoining microcell edges. Long straight edges are subdivided first (up to about 12.8 world units per chord), ensuring curved borders do not fold over themselves. A self-intersection check rejects invalid geometry, and the amplitude backs off only when strictly necessary for simple polygons or the pre-existing **±10% area cap**. The 3D renderer now uses ear-clipped triangles and correct area-weighted sampling inside any concave fine cells. This increases mesh density and CPU generation time; performance still requires in-browser benchmarking.

## Updated procedural pipeline

- **Square macro center → twenty real Voronoi cells → one union outline**. World Lab no longer constructs a macro Voronoi from the square centers. `src/regional-topology.js` now contains the Moore neighbor lookup and polygon area calculation, not an alternative square-site Voronoi generator.
- **Real shared geometry in 3D:** `ConquerRegion3DSnapshot().fineCells` supplies all 12,600 original fine Voronoi polygons. The scene uses ear-clipping to render those same microcells correctly, including when fivefold distortion makes a few of them concave; the aggregated macro outline, which can be concave, is **not** triangulated as a single fan. The 3D detail slider is disabled when this 20-cell source is present, because detail is a fixed property of the source map rather than an independent re-tessellation.
- **Drawing and interaction:** the 2D World Lab's microcell toggle reveals a single SVG path containing all 12,600 fine outlines. The usual territorial selection still maps each fine cell to the associated macro ID; rivers and coastline geometry follow the real shared edges.
- **Terrain and vegetation:** terrain colours come from the original 2D source; trees use the seven original Builder SVG silhouettes and reeds use Builder's scatter model sprites. Hills remain 2–5 truncated-pyramid mesas per hills territory (50% earlier XY and 20% earlier Z); mountain summit height remains halved, with doubled bases, tripled peaks, and snow on the upper third.
- **Marker placeholders:** source-backed village, fortification, harbor, ship and heraldic troops markers are unchanged. Demo-only objects remain explicitly labeled.
- **Camera and performance:** WebGL2 renderer preserves isometry, selection, camera pan/yaw/zoom and independently animated ship markers. Full browser/WebGPU profiling is not yet verified.

## Synthetic CPU benchmark

The previous 8×/20×/40× synthetic benchmarks measure the **fallback standalone Voronoi renderer** when no `fineCells` are present; they do not describe the current World Lab's canonical 20-cell source. The integrated 30×21 map now renders **12,600 real fine polygons** and their shared macro borders without a second overlapping tessellation. Vertex/triangle counts depend on seed, terrain and the newly segmented, sometimes concave fine polygons. Profiling real browsers and GPU FPS remains a separate requirement.

## Verification

- `qa/regional-topology-regression.cjs`: **18 integrated maps** spanning different map sizes, seeds and deformations. Checks exactly square macro centers, **20 fine Voronoi cells per territory**, per-cell size parameter 0.5–1.5, predominantly 5–7-sided fine cells, genuinely irregular aggregated macro outlines, exact polygon union, 8 reciprocal directional neighbors, only logical-neighbor physical borders, and every macro area within ±10%. Also builds a real 3D scene from the same fine polygons and checks its area and count.
- `qa/regional-map3d-regression.cjs`: synthetic fallback geometry, fine-cell area variation, rivers following territory seams, mountains/hills/trees/reeds and 3D territory picking.
- A direct integration check confirmed that a manual river macro-pair maps to **all and only** its shared fine edges in the new 3D geometry.
- Browser screenshot and actual GPU/FPS verification remain pending.

## Regional marker placeholders (visual only)

Five camera-projected 3D primitives are implemented in `src/regional-map3d-placeholders.js`. They use a dedicated upper canvas so ship animation never rebuilds the terrain mesh:

| Live condition | Symbol |
|---|---|
| Village present | Orange cuboid |
| Non-palisade fortification present | Grey cuboid (palisades excluded) |
| Port present | Narrow brown dock strip |
| Ship present | Brown rectangular vessel, oriented along its route |
| Troops with their owner's heraldry present | Two stacked polygonal cylinders, coloured `heraldry.c1` and `heraldry.c2` |

The read-only `ConquerRegion3DMarkerSnapshot()` bridge maps real World Lab `villages`, `fortifications`, `ports`, and optional `regionalShips` / `ships` and `regionalArmies` / `armies`. Troops with unavailable heraldic colours are omitted, not assigned invented player colours. Live ships may supply `{route:[{x,y},...],progress}` and the marker follows their simulation-supplied progress. The `window.ConquerRegion3DLiveMarkers` provider offers a compatible extension point for future integration.

**Current source limitation:** the World Lab deliberately freezes its legacy village/road generation and has no integrated regional ship or army simulation yet. The clearly labelled, default-on checkbox **Esempi visivi (non dati di gioco)** therefore displays one example of each shape, including a boat sailing a looping test route. Demo troops use the actual CONQUER default heraldry field colours from `src/heraldry-shapes.js`, but are not real units. Unchecking that control displays only real source-backed markers. Demo entities never change gameplay, ownership, saves or map data.

Verification: `qa/regional-map3d-placeholders-regression.cjs` covers all five primitives, palisade exclusion, real heraldic colours, route movement and no-fabrication rules. A simulated DOM/WebGL/Canvas integration run validated the independent overlay, live polling and toggle. Full visual/FPS inspection in a real browser remains pending.

## Visual limitations and future integration

- Every macro has eight constant-time **logical neighbors** in a square Moore grid. That does not imply eight physical border-sharing neighbors in the Voronoi tessellation; some diagonals are corner-only relationships. Physical rivers and barriers continue to use actual shared edges.
- Source fine-cell geometries are now authoritative and reused in the 3D preview; there is no longer a separate visual-macro owner reassignment layer for these maps. Rare degenerate microcell arrangements are retried deterministically.
- Tree/reed sprites remain projected 2D billboards, not volumetric, depth-tested 3D vegetation; their occlusion with mountain faces can be imperfect.
- A production renderer should cache meshes by seed/palette/revision and profile low-end hardware, progressive LOD, instancing and worker generation.

## Preview

Serve the repository root over HTTP and open \`/lab/3dregionmap.html\` (do not use \`file://\`). In the left iframe, generate/edit the authoritative 2D map. The right pane detects the 2D revision, then builds its own global microcell mesh. Choose 8/20/40 detail, vary the deformation slider, and toggle tree/reed populations. The benchmark button reports CPU construction time (not GPU FPS).

**Conclusion:** the dense-microcell-first model allows much more organic cartographic contours without changing the canonical game grid. It is a promising experimental direction, but visual and GPU-level assessment is still required.
